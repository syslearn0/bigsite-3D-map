# コミケ 3D マップ（見本）

東京ビッグサイトの会場を 3D で見て、行きたいサークルの計画を立てる Web アプリの見本。
コミックマーケット準備会・株式会社東京ビッグサイトとは関係のない、個人の非公式の試作です。

**いまの島の配置・作品は見本です。C109（2026年12月29〜31日）の本当の配置ではありません。**

## できること
- 見方を3つ切り替える：上から（地図のように）・3D（回して見る）・歩く（一人称。ドラッグで見回し、床をダブルタップするとそこへ進む）
- 1F と 4F を切り替える（西3・4、南3・4 は 4F）
- 「周辺も表示」で、まわりの建物と会議棟（逆ピラミッド）を立体で、道・歩道（2F の歩行者デッキを含む）・ゆりかもめの高架・駅（東京ビッグサイト・国際展示場・有明）を出す（OSM。展示ホールの建物は中が見えるよう立体にしない。地下のりんかい線は駅の名前だけ）。切れば今まで通りの見え方。周辺のデータは `npm run fetch:surroundings` → `npm run build:venue`
- 列（例：東A）→ 番号 → a・b を選んで机へ飛ぶ。机を押すと配置番号が出る（選ぶ欄もその机に変わる）
- 机に「★ 行きたい」か「◆ 候補」の印をつける（この端末の中だけに保存）。印ごとに、地図にピンを立てるかを選べる
- 配置図を印刷する（上の「配置図を印刷」）。同じ建物・同じ階のホールを1枚にまとめて6枚（東1〜3・東7・8・西1・2・西3・4・南1・2・南3・4、A4 横）。島の列が紙に対してまっすぐになるよう回し、北は矢印。列の名前・島の端の番号（机ごとの番号は、読める大きさになるときだけ）・印（★ 行きたい・◆ 候補）の札が入り、図の下に印の一覧。印刷の画面で「PDF に保存」を選べば PDF になる。電波がなくても使える
- 作品ごとの色分け（見本）
- 電波がなくても開ける：一度開くと、画面（会場のデータと机の配置を含む）を端末に持っておく（`public/sw.js`）。ホーム画面に追加すればアプリのように開ける

## データ
| 中身 | 出典 |
|---|---|
| ホール・通路・まわりの建物・トイレの形と位置 | © OpenStreetMap contributors（ODbL 1.0）。`npm run fetch:osm` → `npm run build:venue` |
| 机の配置（見本） | `npm run build:layout` が、ホールの形から仮に並べる。島の大きさはコミケの長机（1800×450mm）、1スペース＝机半分（a・b） |

- ホール同士の位置関係は OSM の緯度経度のまま。
- 南展示棟は OSM（と国土地理院の地図）に建物の外形しかないので、ビッグサイトの主催者向け図面（白図）の寸法を参考に置いた。南1ホールは約67m × 73m、西展示棟の側の端から約36m（エントランスホールなど）の奥に南1、その奥に南2。南3・南4 は 4F で南1・南2 の真上。
- 東1〜3ホールは、OSM の形が通路まで含んで長いので、白図の寸法（90m × 90m）に合わせて通路側を削った。
- 階は、ビッグサイトの図面の表題で確かめた：西1・2 と南1・2 は 1F、西3・4 と南3・4 は 4F。床の高さ（4F＝15m、2F＝6m）は OSM の高さからの目安（施設概要では南1・2 の天井高が 12m なので、4F の床はそれより上）。
- 西1・西2 は L 字のホールで、図面の大きさ（約83m × 135m）と OSM の形が大きく違わないので、OSM の形のまま。
- 西3ホールは図面の寸法（約44m × 106m）に合わせた（OSM は 40m × 93m）。西4 との境目の側はそのままで、反対側へ伸ばした。西4 は OSM の形のまま。
- トイレ・救護室：開いている全ホール（東1〜3・7・8、西1〜4、南1〜4）の図面から読んだ 72 か所と救護室 2 か所（`python scripts/extract-plan-toilets.py` → `data/plan-toilets.json`。数m〜10m ずれうる）。図面の文字が読めるもの（東1・2、西1・2、南1〜4）は自動で、読めないもの（東3・7・8、西3・4）は図面の画像を見て手で読んだ位置。図面を読めていない所は OSM のトイレで補う。
- 出入口・搬入口（シャッター）：図面の「出入口」「エントランス」「搬入口」の文字の位置（出入口 26・搬入口 41）。建物としての位置で、当日どこが開くかは運営の案内による。
- 作り直す順：`npm run build:venue` → `python scripts/extract-plan-toilets.py` → もう一度 `npm run build:venue` → `npm run build:layout`
- 東4〜6ホールは改修工事中のため、C109 では使わない（机を置かない）。
- ビッグサイトの主催者向け図面（白図）は、個人・非営利で参考にすることをビッグサイトに確認したうえで、寸法だけを使っている（形はなぞらない）。図面そのものは再配布できないので、このリポジトリには入れない（`data/private/` は git に入らない）。

## 島のエディタ（/editor）
地図の見出しの「島のエディタ」から開く。作業は2つ。

### 作品・キャラを入れる（協力者。最初に開く画面）
机の位置は作者が用意し、協力者はそこに作品とキャラを入れる。**日ごと（1〜3日目）**に分けて持つ（同じ配置番号でも日が違えば別のサークル）。上の欄で段階を切り替える。
- **① 作品**：作品ごとのまとまりを広い範囲で選び、「ブルーアーカイブ」「原神」などを入れる。地図は作品の色で描く
- **② キャラ**：まずキャラを入れる作品を1つ選ぶ。その作品のスペースだけが選べるようになる（ほかは薄い灰色）。キャラを「、」区切りで入れる。キャラが入った所は濃く、まだの所は薄く描く。「この作品のキャラ」を押すと、そのキャラのスペースを全部選ぶ
- **③ お品書き**：準備会に確認してから、サークル本人に入れてもらう予定（置き場所 `circle` だけ決めてある。共有の保存先とログインが要るので、協力エンジニアの担当）。今は説明だけ

選び方（① ② 共通）：スペースを押す／列の名前（○）でその列を全部／何もない所からドラッグで囲む／Shift＋押すで同じ列の範囲／Ctrl＋押すで足す・外す。右ドラッグで地図を動かす。Delete で、① は作品とキャラを、② はキャラだけを消す。Ctrl+Z で戻す。
入れたものは端末に自動で保存。「書き出す」で作品・キャラのファイル（JSON）にして送れる。「3D で確かめる」で、メインの地図の色分け（作品ごと）と、机を押したときの作品・キャラに出る（地図に日を選ぶ欄が出る）。

### 机の配置（管理用）
カタログの配置図を見ながら、島の列を並べる。
- 下絵：カタログの配置図などの画像を読み込み、半透明で重ねて位置・大きさ・回転を合わせる（「下絵を合わせる」）。画像は端末の中だけで使い、保存も送信もしない
- 島を置く：列の始まり（番号 01 の側の端）と終わりを押す。向きはホールの壁にそろう（Shift で自由な向き）。机の数は長さから決まる
- 選んだ列：列の名前・机の数（横切る通路ごとの区切り、例 16,16）を直す。番号の向きを反対に・90° 回す・消す。平行にコピー（列の名前は次の文字）
- 気になるところ：列の名前の重なり・ホールからのはみ出し・ほかの列との重なり（同じ階）・机の数の誤り
- 「書き出す」で配置のファイル、「3D で確かめる」でメインの地図に出す（地図の「見本に戻す」で見本に戻る）

## 机の配置の形（島のエディタもこの形を書き換える）
`src/data/layout-sample.json` の `lines` が、島の列（ブロック）1つずつ：

```json
{ "hall": "E1", "block": "A", "start": [x, z], "angle": 0.78, "segments": [16, 16], "genre": "作品A" }
```

- `start`：島の中心線の始点（会場の中のメートル。x が東、z が南）
- `segments`：横切る通路で区切られた区間ごとの机の数
- 番号は A側を始点から進み、B側を戻る。机1つが番号1つで、左右の半分が a・b
- 計算は `src/lib/layout.ts` の `expandBooths`
